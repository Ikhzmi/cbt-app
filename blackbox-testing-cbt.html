Hasil Analisis Kode & Temuan Logic/Security yang Wajib Diuji:

Berdasarkan analisis static source code terhadap kode perubahan terbaru (uncommitted changes), berikut adalah potensi bug logic dan celah keamanan yang perlu divalidasi secara ketat:

  • 1. Parameter Tampering pada Livewire saveAnswer(): Method saveAnswer($questionId, $answerId) tidak memvalidasi apakah $answerId benar-benar opsi milik $questionId, atau apakah $questionId tersebut ada dalam daftar soal mapel siswa yang sedang aktif. Siswa teknis berpotensi menyuntikkan answer ID benar dari soal lain.
  • 2. State Public Livewire Tanpa #[Locked]: Properti $historyId, $examId, dan $subjectId dapat dimanipulasi via request Livewire jika tidak diberi atribut #[Locked] di Livewire v3.
  • 3. Konkurensi Memulai Multi-Mapel: Jika siswa membuka tab baru atau merefresh URL ke /mulai saat Mapel 1 masih in_progress, tombol Mapel 2 tetap bisa diklik untuk memulai sesi baru. Hal ini mengakibatkan dua sesi berjalan secara paralel.
  • 4. Data Soal Aktif Kurang dari Pivot qty: Jika admin menyetel kuota soal misal 20, namun di bank soal hanya ada 5 soal aktif, sistem hanya menampilkan 5 soal tanpa peringatan kuota tidak terpenuhi. Jika 0 soal, layar menjadi blank putih tanpa tombol selesai.
  • 5. False Positive pada Anti-Cheat (Blur Event): Event blur dapat terpicu jika siswa mengeklik ekstensi browser, popup password manager, atau sistem notifikasi OS (toleransi maksimal 3x sebelum didiskualifikasi).
